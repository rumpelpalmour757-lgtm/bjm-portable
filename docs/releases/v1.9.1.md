# BJM 通用迁移包 v1.9.1

在本仓库 v1.8.1 上合入作者交来的 v1.9 新加的两样：图执行器的退回审批和 Agent Skills 0.6.17，再按复核改了几处。v1.9 是作者在自己的 v1.8 上做的一版，不含本仓库 v1.8.1 的修改，没有单独发布到本仓库；在本仓库里，这一版接在 v1.8.1 后面。协议的规则、`SKILL.md`、`scripts/`、检查点格式和图执行器的数据库结构与 v1.8.1 相同，v1.8.1 的检查点和图执行器数据库照旧能用。

## 下载哪一个

- **`bjm-portable-v1.9.1.zip`**：整个包，解压出来是 `bjm-portable/` 目录，和仓库里这一版的文件相同（`.github/`、`docs/releases/` 这类仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，包里也有同样的两份。

## 这一版改了什么

- **退回审批（来自 v1.9）**：审批节点等待批准时，审阅者可以用 `reject <节点> -- <令牌>` 退回当前版本。退回的决定存在 SQLite 里，依赖这个审批的步骤一直等着，其他分支照常运行；被退回的节点不接受批准、重试或写回结果，改了上游稿件再运行，才发新令牌。用法见 `graph-runtime/README.md` 的“退回当前版本”。
- **Agent Skills 0.6.17（来自 v1.9）**：`vendor/` 里的 Agent Skills 从 0.6.16 换成 0.6.17，模块从 25 个变成 26 个，新加审查现有界面无障碍问题的 `accessibility-engineering`，另有 4 个模块改过。`references/methods.md` 的模块表加了这一行。原始 ZIP 和官方标签源码 ZIP 逐字节相同，展开目录照旧和 ZIP 逐字节相同、保留 9 个 shell 脚本的可执行位。
- **按复核改的地方**：
  - 退回按内容记。v1.9 只按带修订号的指纹认版本，把稿件改成别的再改回来，或者往上游加一个不影响输出的输入，被退回的同一份内容会重新送审。现在退回时记下送审内容的摘要；在同一个运行里，同一份内容再到这个审批节点时保持退回、不发令牌，并在事件和 `error` 里写明是哪一次退回的。经过旧版本的库里，旧版本对这份内容发的令牌也不能用来批准。要让审阅者重看同一份稿件，改审批节点自己的输入，这是有意留的做法。对照按依赖节点的输出逐字节比较：审批排在 Claude Code 审查节点后面时，审查每次重跑的会话 ID 都不同，排在另一个审批后面时，前一个审批的输出里有带修订号的指纹，这两种图里改稿以后同一份稿件仍会再次送审，要靠审阅者自己核对。
  - 批准和退回被拒时，报错写明是节点已经批准、已经退回、还没发令牌，还是根本不是审批节点；只有令牌不对或过期，才说令牌无效。
  - `run` 不加 `--claude` 时，排在等待批准或被退回的审批后面、这次轮不到的 Claude Code 审查节点不再让整次运行报错，无关分支照常能跑。审查节点的声明照旧全部核对，轮不到的也查，声明被 `edit` 改坏了，第一次 `run` 就报错。
  - 图执行器改称 v0.1.5。v1.9 包里把加了 `reject` 的那一版叫作 v0.1.4，和本仓库 v1.8.1 的 v0.1.4 撞了名。
  - 测试：v1.9 新加的两项移过来，改数据库的连接改成用完就关，令牌前一律加 `--`；另加八项，钉住上面几处，也拦住复核时试出的几种错误改法。
- **说明文字**：`graph-runtime/README.md` 的退回一节改写成第二条批准命令的另一种做法（v1.9 的写法接在已经批准以后，照做只会报令牌无效），写明 `REJECTED` 有两种来源、该改哪里。`README.md` 的版本、下载按钮、模块数、测试数、入口表、令牌一句的版本、“可选的图执行器”一段（`reject` 和 `--claude` 的规则）、包内组件和署名改成这一版的。`THIRD-PARTY-NOTICES.md` 改成 0.6.17 的版本、路径、SHA-256 和提交，版权行不变，并写明 OpenAI Agents SDK v0.25.0 和 Temporal OSCAR 只作参考。`references/bjm-v3.2.md` 附录 C“改编依据”的说明改成 0.6.17，协议正文没有改。`CHANGELOG.md` 收录了 v1.9 自带的版本记录，并在和本仓库版本线对不上的地方加了注。

## 验证到哪一步

- `tests/` 下 53 项（BJM 36 项、匿名对照材料 12 项、收票 5 项）：在 Linux 上用 Python 3.11.17、3.12.3、3.13.17 各跑一遍，全部通过。这次没有 Python 3.9，v1.8.1 时跑过的 3.9 这次没有再跑。
- `graph-runtime/tests/` 下 33 项：在 Linux 上用 Python 3.11、3.12、3.13 各跑一遍，全部通过，没有跳过的项；加 `-X dev` 跑，测试进程里没有 `ResourceWarning`。跑测试时命令搜索路径只有 `/usr/bin` 和 `/bin`，在那里找不到真的 `claude`；`test_claude_cli.py` 的 12 项照旧只把模拟程序所在的目录交给子进程。
- 这一版新加的 8 项里有 6 项，连同改过断言的 1 项，放在只做了三方合并、没按复核改的代码上跑都失败，改完以后都通过；另外 2 项在那份代码上本来就成立。复核时造了几种错误改法（查退回时不按运行或不按节点过滤、预检漏掉中断后能自动重跑的节点、把等待批准的审批当成已经通过、声明只查这次能轮到的审查节点、`approve` 不和以前的退回对照等），每一种都有测试失败；只有“没经过预检的审查节点不启动程序”这道保险，正常代码走不到，去掉它测试看不出来。
- 演示 `graph-runtime/demo.py`：在 Python 3.13 上连续跑了 30 次，都通过。照 `graph-runtime/README.md` 逐条做到等待批准，旧令牌被拒，再用新令牌 `reject`，节点记为退回，事件里有 `APPROVAL_REJECTED`。
- 照复核的几种做法实跑：退回后把稿件改成别的再改回来、往上游加一个不影响输出的输入，审批节点都保持退回、不发令牌；改审批节点自己的输入，重开审批。用每次返回新会话 ID 的假 `claude` 跑 `examples/claude_review.json`，退回后往稿件里加一个不影响输出的键，审批照样发了新令牌，和说明里写的一样。挂在审批后面的审查节点被 `edit` 把 `focus` 改空，第一次 `run` 就报错，哪一支都没开跑。审查节点挂在被退回的审批后面时，不加 `--claude` 的 `run` 能跑完无关分支，命令搜索路径前面放的一个只记日志的假 `claude` 一次也没被启动。
- 兼容：v1.8.1 建的库交给 v1.9.1，能续跑、退回 v1.8.1 发的令牌、改稿后批准并走完下游，`user_version` 仍是 1。v1.9.1 写了退回的库交给 v1.8.1：下游照样等着，`approve`、`retry`、`resolve` 都被拒，`reject` 报用法错误；往上游加一个不影响输出的输入以后，v1.8.1 对同一份内容发了新令牌，因为 v1.8.1 不按内容对照；这个令牌在 v1.8.1 里能批准，批准后下游走完。不在 v1.8.1 里批准、把库拿回 v1.9.1 再用这个令牌批准，报这份内容在修订号 1 退回过，库里什么也不写，`reject` 照常能用。作者的 v1.8 打开这个库，结果相同。作者 v1.9 退回的库交给 v1.9.1 能续跑，那次退回没有内容摘要，不按内容对照；v1.9.1 的库交给作者 v1.9，被退回的节点照样拦住下游。
- `vendor/`：用只读的脚本对照官方 ZIP 和展开目录，261 个普通文件逐字节相同，只少 `.opencode/` 的符号链接，ZIP 里可执行的 9 个文件在仓库里也记为可执行；`references/methods.md` 的 26 个链接都能打开，正好对上 `skills/` 下的 26 个目录。`vendor/` 下的脚本一律没有运行。
- 用 `git archive` 在临时克隆里模拟了发布包：包的根目录没有 `.github/`、`docs/releases/`、`.gitattributes` 和 `.gitignore`（`vendor/` 里上游自带的同名文件照原样保留），`vendor/` 下 9 个 shell 脚本保留了可执行位；解开后两套测试和演示都通过。
- 泄露检查：没有私人路径；示例和测试里的稿件只有原有的那段虚构文字和几句通用的测试句子。
- 测试和检查都是同一个模型（Claude）的新实例做的，不是独立评审。

## 没有验证的

- 真实的 Claude Code 调用，和 v1.8.1 一样没有用真的 `claude` 试过。
- v1.9 引的 OpenAI Agents SDK v0.25.0 发布页、Temporal OSCAR 案例两个链接和它们的日期，没有联网核对。
- Agent Skills 0.6.17 新模块的内容没有逐条审读，它的审查脚本要联网下载 npm 包，没有运行；这些模块和 BJM 一起用的效果没有测。
- Windows、macOS，Python 3.9 和 3.10。
