# BJM 通用迁移包 v1.10.1

在本仓库 v1.9.1 上合入作者交来的 v1.10 新加的 `run --claude-workers`，再按复核改了几处。v1.10 是作者在本仓库 v1.9.1 的发布包上做的一版，没有单独发布到本仓库；在本仓库里，这一版接在 v1.9.1 后面。协议、`SKILL.md`、`scripts/`、`tests/`、`vendor/`、检查点格式和图执行器的数据库结构与 v1.9.1 相同，v1.9.1 的检查点和图执行器数据库照旧能用。

## 下载哪一个

- **`bjm-portable-v1.10.1.zip`**：整个包，解压出来是 `bjm-portable/` 目录，和仓库里这一版的文件相同（`.github/`、`docs/releases/` 这类仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，包里也有同样的两份。

## 这一版改了什么

- **限定同时在跑的审查数（来自 v1.10）**：图执行器的 `run` 新加可选的 `--claude-workers N`。同一张图里既有本地任务又有 Claude Code 审查时，例如 `run --claude --workers 4 --claude-workers 1`，同时最多跑 4 个任务节点，其中审查最多 1 个；其余审查排着等，不算尝试次数，不依赖它们的本地任务照常跑。一个审查结束，不论成功、失败、待核还是被拒，就空出一个名额。上限只管这一次 `run`，不存进数据库，要限的每次都得再加；不加时和 v1.9.1 一样只按 `--workers` 算。用法见 `graph-runtime/README.md` 的“使用 Claude Code 并行审稿”。图执行器改称 v0.1.6。
- **按复核改的地方**：
  - `--claude-workers` 填 0 或负数时，报错写明是这个参数要正整数（v1.10 报的是引擎内部的说法）；引擎在 `worker_limits` 不是映射时也报同样的错。
  - 说明里写明：不加 `--claude` 时这个选项不起作用；比 `--workers` 大时，实际并发仍不超过 `--workers`；调度进程被强行结束以后，它启动的 Claude Code 进程可能还在跑，不算进下一次 `run` 的上限，要先确认上次的调用已经结束再续跑。
  - 测试：v1.10 的两项新测试移过来。命令行那项原来依赖两份初稿谁先跑完，改成和先后无关的比较；调度那项把等待时限放宽。另加三项，钉住审查失败、待核或被拒以后照样空出名额，`--workers` 和审查上限同时顶到时两个上限都守住，以及取值不对时在碰库以前报错。
- **说明文字**：`graph-runtime/README.md` 补回 v1.10 删掉的验证范围一句，新加的用法一段改写后挪到示例说明后面，设计参考里 ADK 一条改成“参考”并写清两者的差别。`README.md` 的版本、测试数、图执行器版本、用法一段、测试说明和署名改成这一版的；v1.10 换掉的下载按钮和下载说明保留仓库原来的写法。`THIRD-PARTY-NOTICES.md` 写明 Google ADK v2.15.0 只作参考。`CHANGELOG.md` 收录了 v1.10 自带的版本记录，并在和本仓库版本线对不上的地方加了注。

## 验证到哪一步

- `tests/` 下 53 项（BJM 36 项、匿名对照材料 12 项、收票 5 项）：在 Linux 上用 Python 3.11.17、3.12.3、3.13.17 各跑一遍，全部通过。这次没有 Python 3.9，v1.8.1 时跑过的 3.9 这次没有再跑。
- `graph-runtime/tests/` 下 38 项：在 Linux 上用 Python 3.11、3.12、3.13 各连跑 5 遍，共 15 遍，每遍 38 项全部通过，没有跳过的项；Python 3.13 加 `-X dev` 跑一遍，没有 `ResourceWarning`。跑测试时命令搜索路径只有 `/usr/bin` 和 `/bin`，在那里找不到真的 `claude`；`test_claude_cli.py` 的 13 项照旧只把模拟程序所在的目录交给子进程。
- 错误改法：在副本里逐一造了几种错误改法，每一种都有测试失败：去掉审查上限的判断、把 `>=` 改成 `>`、派出后不加计数、结束后不放回名额、只在成功时放回名额、去掉 `--workers` 的总数检查、命令行不把上限传给引擎、去掉命令行的取值检查、去掉引擎的取值检查、去掉“必须是映射”的检查。其中“只在成功时放回”和“去掉总数检查”两种，v1.10 的 35 项看不出，现在分别由新加的两项拦住。
- 命令行测试的先后问题：在副本里给初稿 a 加 0.5 秒延迟，让 `review-b` 先开跑，改过的测试照样通过；v1.10 的写法在这时失败，是复核时试出来的。
- 命令行：`--claude-workers 0` 和 `-1` 报 `--claude-workers must be a positive integer`，退出码 2，库里的事件和运行前相同；`1.5`、`abc` 由命令行解析报错，退出码 2。
- 演示 `graph-runtime/demo.py`：在 Python 3.11、3.12、3.13 上各跑一遍，再在 3.13 上连续跑 30 次，都通过。
- 兼容：用一张有两份初稿、三个审查、一个本地任务、一个审批和审批后一个任务的图，同一个库在 v1.9.1 和 v1.10.1 之间交替运行，Claude Code 用测试里的模拟程序。失败的审查由另一版 `retry` 后只补跑这一支，已完成的审查沿用原结果；一版发的令牌在另一版能批准、能退回，退回后再跑状态不变、被退回的令牌不能批准，改稿后只重跑那一章和它的审查；v1.10.1 带上限 1 运行时被 SIGKILL 杀掉，v1.9.1 能续跑，被中断的审查照 `retry_on_interrupt: false` 进入 `UNCERTAIN`。全程 `user_version` 是 1。v1.9.1 遇到 `--claude-workers` 报用法错误，退出码 2。带上限被杀以后不加 `--claude-workers` 续跑，两个审查同时开跑，上限确实没有存进库里。不加 `--claude-workers` 时，两章演示图和 Claude Code 示例图的同一串命令在 v1.9.1 和 v1.10.1 上写出的事件逐条相同，命令结果只有随机令牌不同。
