# BJM 通用迁移包 v1.8.1

在作者交来的 v1.8 上合入本仓库 v1.5.1 的修改和仓库这边的封面、许可文件，再按复核改了几处。v1.6、v1.7、v1.8 是作者用另一个 Claude 会话在 v1.5 上做的三版，没有单独发布到本仓库；在本仓库里，这一版接在 v1.5.1 后面。协议正文、`scripts/workflow.py`、`scripts/blind_review.py`、检查点格式和附带的 Agent Skills 0.6.16 与 v1.5.1 相同，v1.5.1 的检查点和图执行器数据库照旧能用。

## 下载哪一个

- **`bjm-portable-v1.8.1.zip`**：整个包，解压出来是 `bjm-portable/` 目录，和仓库里这一版的文件相同（`.github/`、`docs/releases/` 这类仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，包里也有同样的两份。

## 这一版改了什么

- **用 Claude Code 审稿（来自 v1.8）**：图执行器新加 `claude-review` 节点。只有运行 `run --claude` 时，它才启动本机另装的 Claude Code，在不带工具的独立会话里按节点的审查要求审一份稿件；BJM 核对报告的格式和引句是否出自稿件，保存报告、会话 ID、稿件摘要、请求的模型和报告里列出的实际模型，两份报告都保存以后才进入人工审批。示例是 `graph-runtime/examples/claude_review.json`，用法见 `graph-runtime/README.md`。真实调用没有验证过，测试和演示都用本地模拟的命令行程序。
- **图执行器的其他新东西（来自 v1.6、v1.7、v1.8）**：适配器能确认输入必须改、这次没有产生外部效果时，节点记为 `REJECTED`，改了输入再继续；`retry_on_interrupt: false` 让节点在调度中断后不自动重发；输入指纹只在节点真正派发时才算。批准令牌一律以 `bjm_` 开头，不会再被命令行当成选项。
- **收票核对（来自 v1.7）**：`scripts/check_review_votes.py` 按主持人保存的名单逐张核对已收的选票，一次列出缺的票和坏的票，有效票保留，只向有问题的审查者补收。说明在 `references/blind-review.md`。
- **按复核改的地方**：
  - 审查节点被中断、进入待核以后，以前 `retry` 和 `edit` 都不接受，只能用 `resolve` 填一份没人核过的报告；现在声明了 `retry_safe` 的节点可以 `retry`。
  - `REJECTED` 的节点写明被拒的原因；审查节点的依赖数、`focus` 或 `model` 不合格时，`init` 和 `run` 在任何分支开跑以前就报错。
  - 角色提示要求把稿件里冲着审稿者说的话、想改动审查要求的话单独列成结论，作品本身的对白和叙述（例如故事里人物对 AI 说的话）不算；只有标点的引句不算出自稿件，角色提示也写明了这一条，查标点问题时要连同前后的字一起引；Claude Code 自己的报错显示在终端上。
  - 因为上面这几处改了行为，图执行器改称 v0.1.4（v1.8 包里是 v0.1.3）。
  - 调用 Claude Code 的测试只让模拟程序出现在命令搜索路径里，并去掉密钥类的环境变量，模拟程序不能执行时整组跳过。v1.8 的写法在临时目录不能执行程序时，会找到真的 `claude`，把测试稿件发出去。
  - 收票脚本接受带 BOM 的文件；JSON 嵌套极深时，按坏票或名单不可用报告，不再打出 Python 的内部错误。
- **合回 v1.5.1 和更早的修改**：v1.8 是在 v1.5 上做的，匿名对照材料脚本、它的测试和说明仍是 v1.5 的原样，`SKILL.md` 少了“中文小说用小说写作工坊”那句，协议里改编依据的更正也没有。这一版全部用回仓库的，再把 v1.8 新加的收票说明接上。`README.md` 保留封面和三节介绍，`LICENSE`、`THIRD-PARTY-NOTICES.md`、`.gitignore`、`.gitattributes`、发布工作流和发布说明照旧保留；`vendor/` 下 8 个 shell 脚本保留可执行位。
- **说明文字**：`graph-runtime/README.md` 写明审查节点被中断以后报告和会话 ID 都找不回来，确认可以再次计费后 `retry`；`resolve` 写回的内容不经过核对；报告里没有结论不等于稿件没有问题。`references/blind-review.md` 写明选票的 `choice` 只能是 `"A"`、`"B"` 或 `"tie"`，列出待补的六种原因。`THIRD-PARTY-NOTICES.md` 写明达尔文 v3.0.2、Temporal、OpenAI Agents SDK 和 Claude Code 只作参考，包里没有它们的代码；Claude Code 要使用者自己安装。`CHANGELOG.md` 保留了 v1.6、v1.7、v1.8 自带的版本记录，并在和本仓库版本线对不上的地方加了注。

## 验证到哪一步

- `tests/` 下 53 项（BJM 36 项、匿名对照材料 12 项、收票 5 项）：在 Linux 上用 Python 3.9.25、3.11、3.12、3.13 各跑一遍，全部通过。
- `graph-runtime/tests/` 下 23 项：在 Linux 上用 Python 3.11、3.12、3.13 各跑一遍，全部通过，没有跳过的项。其中 `test_claude_cli.py` 的 11 项用模拟的 Claude Code 命令行程序；跑测试时，命令搜索路径只有 `/usr/bin` 和 `/bin`，在那里找不到真的 `claude`，测试自己又只把模拟程序所在的目录交给子进程。
- 这一版新加或改过的测试，放在没改过的 v1.8 代码上跑，有 10 项失败或出错（收票 1 项、图执行器 9 项），改完以后都通过；新加的“找不到 `claude` 命令时停下”和改过的令牌前缀两项，在 v1.8 上本来就能过。模拟程序设成不能执行、命令搜索路径后面放一个只记日志的假 `claude` 时，v1.8 的测试把这个假 `claude` 启动了 10 次；这一版 11 项全部跳过，假 `claude` 一次也没被启动。
- 演示 `graph-runtime/demo.py`：在 Python 3.13 上连续跑了 30 次，都通过。
- 用模拟的命令行程序照 `graph-runtime/README.md` 跑了 Claude Code 审查示例：一支审完、另一支还在跑时杀掉调度进程，再运行时那一支进入 `UNCERTAIN`，`edit` 被拦住，`retry` 以后只补跑那一支，另一支的报告原样沿用，随后进入等待批准。
- 回退：用 v1.8.1 建的库交给 v1.5.1 的图执行器，能打开、能续跑；`REJECTED` 的节点 v1.5.1 不接受 `retry`，改了输入以后能续跑；`retry_on_interrupt: false` 的节点被中断后，v1.5.1 把它自动重排又做了一次；审查节点在 v1.5.1 下按未知操作处理，不发出调用，声明了 `retry_safe` 的记为 `FAILED`，没声明的记为 `UNCERTAIN`。v1.5.1 建的库交给 v1.8.1 也能续跑和批准。
- 用 `git archive` 在临时目录里模拟了发布包：包里没有 `.github/`、`docs/releases/`、`.gitattributes` 和 `.gitignore`，`vendor/` 下 8 个 shell 脚本保留了可执行位；解开后两套测试和演示都通过。
- 泄露检查：没有私人路径；示例和测试里的稿件只有 v1.8 自带的那段虚构文字和几句通用的测试句子。
- 测试和检查都是同一个模型（Claude）的新实例做的，不是独立评审。

## 没有验证的

- 真实的 Claude Code 调用：模型会不会照角色提示把稿件里夹带的指令列成结论、会不会把故事里人物对 AI 说的话误列进去、查标点问题时会不会连同前后的字一起引，`--bare` 模式下的凭据，`modelUsage` 里实际列出哪些模型，以及说明里建议的 Claude Code 版本，都没有用真的 `claude` 试过。
- 匿名对照材料和收票核对没有用在真实的两版对照上，没有测量评审质量。v1.6、v1.7、v1.8 记录里说的本地验收，包里没有记录，无法复核。
- Windows、macOS，包括 Windows 上的 SQLite 文件删除、命令行程序的查找和文件权限。
- Python 3.10。
