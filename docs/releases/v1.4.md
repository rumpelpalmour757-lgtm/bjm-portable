# BJM 通用迁移包 v1.4

明确交付、做一次核对、再交结果的通用工作流。从包里的 `SKILL.md` 开始用；这一个文件就可以单独交给 AI。

## 下载哪一个

- **`bjm-portable-v1.4.zip`**：整个包，解压出来是 `bjm-portable/` 目录，和仓库里的文件相同（`.github/`、`docs/releases/` 这类仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，包里也有同样的两份。

## 这一版改了什么

在 v1.3 上做，BJM 自己的部分没有变：`SKILL.md`、`references/bjm-v3.2.md`（BJM v3.2 完整协议）、`references/runtime.md`、`scripts/workflow.py`、`examples/`、`tests/` 和 `graph-runtime/`（图执行器 v0.1）都和 v1.3 逐字节相同，数据格式也相同，v1.3 可以照旧独立使用。

- 附带的 Agent Skills 从 0.6.15（main 分支快照）换成 [0.6.16 标签版](https://github.com/addyosmani/agent-skills/releases/tag/0.6.16)，仍是 25 个模块。改了 9 个：规格演进（`spec-driven-development`）、文档漂移核对（`documentation-and-adrs`）、前端验证（`frontend-ui-engineering`）是新增的方法；计划模板、安全清单（OWASP 2025 编号）和几个模块的触发描述也有改动。其余 16 个不变。
- `README.md`、`references/methods.md`：版本号和 vendor 路径改成 0.6.16；新加 `CHANGELOG.md`。
- 开仓库时加了：`LICENSE`（MIT，版权人 Celeste）、`THIRD-PARTY-NOTICES.md`、`.gitignore`、`.gitattributes`，`README.md` 末尾加了“获取和许可”一节。`vendor/` 下 8 个 shell 脚本照上游 ZIP 恢复了可执行位。

## 验证到哪一步

- 包里自带的测试：BJM 36 项、图执行器 6 项，在 Linux、Python 3.13 上全部通过。README 里的两条 `workflow.py` 示例和 `graph-runtime/demo.py` 都跑通，示例照说明给出 `RECHECK`。
- `vendor/agent-skills-0.6.16.zip` 的 SHA-256 是 `6f0304fe35188526f27541e913b9aeff60663ae076c04c65090df12875aeec48`，和 `CHANGELOG.md` 写的一致；它是不是和 GitHub 上的官方 ZIP 逐字节相同，没有联网核对。展开目录的 251 个普通文件和这个 ZIP 逐字节相同，只少了 ZIP 里的一个符号链接（`.opencode/skills`）。
- `scripts/workflow.py` 和 `graph-runtime/` 只用 Python 标准库，不联网、不调外部命令；图执行器只往 `--db` 指定的 SQLite 文件和它旁边的锁文件、日志文件里写。`vendor/` 里没有装上就自动运行的东西，`hooks/` 下的脚本要人手动接线才会动。
- 测试和评估都是同一个模型（Claude）的新实例做的，不是独立评审。

## 没有验证的

- 在各个宿主里实际装上以后会不会误触发，比如和别的技能抢请求。
- Windows、macOS。
- 0.6.16 里改过的 6 个上游路径，`references/bjm-v3.2.md` 的“改编依据”还没有逐条重新对照。
