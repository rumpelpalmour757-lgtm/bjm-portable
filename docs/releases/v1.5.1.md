# BJM 通用迁移包 v1.5.1

在 v1.5 上合入 v1.4.1 的修改和仓库这边的封面、许可文件，修了图执行器批准令牌偶尔以“-”开头的问题，并按复核改了匿名对照材料脚本。v1.5 是作者另外采纳的一版，没有单独发布到本仓库；在本仓库里，这一版接在 v1.4.1 后面。协议正文、`SKILL.md`、`scripts/workflow.py` 和附带的 Agent Skills 0.6.16 与 v1.4.1 相同，v1.4.1 的检查点和图执行器数据库照旧能用。

## 下载哪一个

- **`bjm-portable-v1.5.1.zip`**：整个包，解压出来是 `bjm-portable/` 目录，和仓库里这一版的文件相同（`.github/`、`docs/releases/` 这类仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，包里也有同样的两份。

## 这一版改了什么

- **匿名对照材料（来自 v1.5）**：`scripts/blind_review.py` 从基线和候选两份实际产出生成随机排成 A、B 的审查材料，版本对应关系另存一个映射文件；共用说明或产出里出现已知的版本路径、文件名或标记时，停下不生成。用法见 `references/blind-review.md`，测试在 `tests/test_blind_review.py`。
- **按复核改的地方**：加了 `--packet-out`，材料文件和映射文件都只新建、不覆盖，出错退出时删掉这一次新建的文件；写到标准输出失败时不再留下映射文件。标记比较时统一全角半角、大小写、斜杠和反斜杠，去掉零宽字符，另外查网址解码后和去掉空白后的正文，JSON 转义和全角写法的路径不再漏过。只有 BOM 或零宽字符的文件按空文件拒绝，编码出错时说明是哪一份输入，两份产出的换行符、BOM 或末尾换行的个数不一致时给出提示。说明重写，写清了自动检查哪些标记、怎样比较、哪些写法还查不到，以及映射文件要放在审查者拿不到的地方。匿名对照材料的测试从 6 项增加到 12 项。
- **图执行器的批准令牌**：以前令牌约有 1/64 的机会以“-”开头，命令行会把它当成选项，报错退出（以“-h”开头时多半只打出帮助，退出码为 0），都不会批准，演示和一项测试因此偶尔失败。现在生成时避开“-”开头；`graph-runtime/README.md` 里手动批准的命令、演示和测试都在令牌前加了 `--`。旧数据库里已经存下的以“-”开头的令牌不会自动更换，写成 `approve approve -- '<令牌>'` 就能批准。图执行器的测试从 6 项增加到 8 项。
- **说明文字**：`README.md` 的版本、下载按钮和测试数改成这一版的，“包内入口”表加了匿名对照材料一行，令牌已知问题那段改成已修，并写明旧数据库里的令牌批准时要加 `--`。`THIRD-PARTY-NOTICES.md` 写明达尔文（alchaincyf/darwin-skill）只作参考，仓库里没有它的代码。`CHANGELOG.md` 保留了 v1.5 自带的版本记录，并在和本仓库版本线对不上的地方加了注。

## 验证到哪一步

- `tests/` 下 48 项（BJM 36 项、匿名对照材料 12 项）：在 Linux 上用 Python 3.9.25、3.11、3.12、3.13 各跑一遍，全部通过。
- `graph-runtime/tests/` 下 8 项：在 Linux 上用 Python 3.11、3.12、3.13 各跑一遍，全部通过；在 Python 3.13 上连续跑 40 遍，都通过。在 Python 3.9.25 上也通过了，但图执行器说明里写的最低版本仍是 3.10。
- 演示 `graph-runtime/demo.py`：在 Python 3.13 上连续跑了 200 次，在 3.11 和 3.12 上各跑了 50 次，都通过。
- 匿名对照材料脚本另外手动试过：标准输出写到 `/dev/full`、标准输出已关闭，以及管道提前断开且写入失败时（材料大过管道缓冲区），都以退出码 1 和脚本自己的报错结束，不留下映射文件，修好后照原命令重跑能成功。材料小于管道缓冲区时，下游提前断开，脚本察觉不到，退出码仍是 0，所以说明里要求用 `packet_sha256` 核对。标准错误已关闭或写不进去（`/dev/full`）时：成功的运行退出码为 0，材料里不会混进格式不一致的提示，两个文件都保留；命中标记的运行退出码为 1，不留下文件。两份约 34 MB 的产出加 20 个标记，约 7 秒完成，内存峰值约 505 MB。
- 用 `git archive` 在临时目录里模拟了发布包，包里没有 `.github/` 和 `docs/releases/`，`vendor/` 下 8 个 shell 脚本保留了可执行位；解开后两套测试在 Python 3.9.25、3.11、3.12、3.13 上都通过，`README.md`、`graph-runtime/README.md` 和 `references/blind-review.md` 里的命令逐条跑过，结果和说明一致。
- 泄露检查：没有作者的小说、原话和私人路径。
- 测试和检查都是同一个模型（Claude）的新实例做的，不是独立评审。

## 没有验证的

- 匿名对照材料没有用在真实的两版对照上，没有调用真实模型，也没有测量评审质量。v1.5 记录里说的本地合成对照，包里没有记录，无法复核。
- Windows、macOS，包括 Windows PowerShell 5.1 保存标准输出时改编码、Windows 上新建映射文件的方式和文件权限。
- Python 3.10。
- 达尔文两个版本是不是正式版，只看了 GitHub 网页，没能用 GitHub API 核对。
